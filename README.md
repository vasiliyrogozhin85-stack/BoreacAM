# BoreacAM 1.0

**BoreacAM** — Android-приложение для отправки и получения файлов через динамик и микрофон без интернета и облака.

## Интерфейс

- заставка **Powered by Boreac**;
- стиль BOSS: тёмный фон, холодный синий акцент, минимальное число действий;
- кнопка **«Отправить файл»**;
- кнопка **«Получить файл»**;
- прогресс и понятный статус операции.

## Совместимость

Реализован акустический протокол **AudioModem 3.2.3**:

- PCM 48 кГц, mono, 16-bit;
- 16‑QAM/OFDM;
- 16 поднесущих, 14 информационных и 2 пилотные;
- полезный символ 80 samples + cyclic prefix 16;
- диапазон 1,8–10,8 кГц;
- 7 байт на QAM-символ;
- payload до 1024 байт;
- заголовок 36 байт;
- CRC32 пакета и всего файла;
- кадры DATA и END;
- DATA передаётся два раза, как в Excel-версии.

Имя исходного файла протокол 3.2.3 не передаёт. При получении пользователь заранее выбирает имя выходного файла.

## Передача

1. Нажать **«Отправить файл»**.
2. Выбрать любой файл.
3. Держать динамик телефона рядом с микрофоном принимающего устройства.
4. Не изменять громкость и не закрывать приложение до завершения.

## Получение

1. Нажать **«Получить файл»**.
2. Выбрать имя и папку результата.
3. Разрешить микрофон.
4. Запустить передачу на втором устройстве.
5. После окончания звука нажать **«Остановить и сохранить»**.
6. Приложение декодирует запись и проверит CRC32.

## Сборка APK через GitHub

В проект включён workflow:

```text
.github/workflows/build-apk.yml
```

Результат — артефакт `BoreacAM-debug`.

## Termux: загрузка в GitHub, сборка и установка

Распаковать архив проекта и выполнить:

```bash
cd ~/storage/downloads/BoreacAM
bash scripts/termux_upload_build_install.sh
```

Скрипт:

1. подключит GitHub CLI;
2. создаст репозиторий `vasiliyrogozhin85-stack/BoreacAM`, если его ещё нет;
3. загрузит исходники;
4. запустит GitHub Actions;
5. скачает APK в `Download/BoreacAM-debug.apk`;
6. откроет системный установщик Android.

## Технический статус

Цифровой QAM-loopback и полный encode/decode протокола проверяются отдельным JVM-тестом. Реальный акустический канал зависит от динамика, микрофона, автоматической обработки аудио и акустики помещения. Первые тесты рекомендуется выполнять на расстоянии 10–30 см и с небольшими файлами.
